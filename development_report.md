## 1. Техническое задание (Шаг 1)

| Пункт | Решение |
|---|---|
| Идея | Каталог туров и онлайн-бронирование мест |
| Стек | React 19 + TypeScript strict + Vite |
| UI-библиотека | Tailwind CSS 4 |
| Тесты | Vitest + Testing Library + jsdom |
| Данные | Слой `api/` с двумя реализациями: mock (ДЗ 4) и Supabase (ДЗ 5) |

**Основные функции (7, минимум 3):**

1. Каталог туров: страна, даты вылета и возвращения, число ночей, цена за человека, свободные места
2. Добавление тура (форма с валидацией полей)
3. Удаление тура (только автором)
4. Бронирование: выбор числа гостей (1–10, не больше свободных мест), стоимость в подписи кнопки
5. «Мои брони»: список своих бронирований с итоговой суммой
6. Отмена брони (места возвращаются в тур)
7. Фильтр по стране; ближайшие вылеты сверху; тур без мест нельзя забронировать

**Нефункциональные:** адаптивность (от 375 px), тап-цели не меньше 44 px, состояния loading/error/empty, доступность (подписи полей, `aria-*`, `role="alert"`).

## 2. Инициализация проекта (Шаг 2)

Промпт агенту (исходный проект):

```
Создай проект React + TypeScript на Vite. Подключи Tailwind CSS 4 через плагин @tailwindcss/vite,
Vitest с окружением jsdom и Testing Library. Структура: src/features/<feature>/{components,hooks,api,types},
```

Результат: `package.json`, `vite.config.ts` (плагины react и tailwind, блок `test`), `src/test/setup.ts`, `tsconfig` со `strict`. Правила проекта из ДЗ 2 лежат в `CLAUDE.md` в корне, Claude Code читает их автоматически (при смене темы обновлено только описание проекта в правиле 3). Dev-сервер с hot reload: `npm run dev`.

## 4. Компоненты и состояния (Шаг 4)

Использованы шаблоны из ДЗ 2: «генерация компонента по описанию» и «написание тестов». Пример промпта по шаблону RTCF (для формы тура):

```
## Role
Ты — Senior React/TypeScript-разработчик.
## Task
Реализуй компонент TourForm: поля «Название», «Страна», «Дата вылета», «Ночей», «Мест»,
«Цена за человека». Валидация при отправке, ошибки под полями (aria-invalid, aria-describedby).
После успешного создания форма очищается, при ошибке сервера введённые данные сохраняются.
## Context
Валидация вынесена в чистую функцию validateTourForm в validation.logic.ts. Значения полей
хранятся строками, в API уходят числа (toNewTour). Данные приходят через проп onSubmit.
## Format
План, код с // path:, тесты Vitest + Testing Library, команда проверки.
```

**Состояния (loading / error / success):**

| Состояние | Что видит пользователь |
|---|---|
| loading | «Загружаем путёвки…» (`role="status"`), кнопки действий блокируются на время запроса |
| error загрузки | Красный баннер с понятным текстом и кнопкой «Повторить» |
| error действия | Баннер над списком (запись остаётся на месте); при нехватке мест список мест обновляется |
| empty | «Пока нет путёвок. Добавьте первую через форму.»; для брони: «У вас пока нет бронирований» |
| success | Карточки туров |

Данные для проверки отображения: `MOCK_SEED` (6 туров, среди них один без мест) в `mockToursApi.ts`. Ошибку можно вызвать адресом `/?mock=network-error` в режиме mock.

**Что нашлось при отладке (реальные случаи этой версии):**

| # | Проблема | Как нашли | Решение |
|---|---|---|---|
| 1 | Тест упал: «найдено несколько элементов с подписью "Страна"». Это поле формы и фильтр каталога | Вывод Vitest | Фильтр переименован в «Фильтр по стране»: у двух разных элементов управления не должно быть одинаковой подписи и для скринридера |
| 2 | Тест упал: «найдено несколько элементов с текстом "Мальдивы"». Совпали название тура и страна | Вывод Vitest | Поиск уточнён до заголовка (`role="heading"`) |
| 3 | Линтер: `setState` в эффекте при загрузке (`useTours.ts`) | `npm run lint` | Загрузка вынесена в `fetchAll` (без синхронной смены статуса) и `reload` для кнопки «Повторить». Предупреждение осталось: линтер не различает, что `setState` вызывается после `await`. Ложное срабатывание, оставлено намеренно |
| 4 | Регистрация показывала «Ошибка на сервере» при лимите писем Supabase (HTTP 429) | Логи Auth в Supabase Dashboard | Добавлен отдельный тип `rate-limit` и сообщение «Слишком много запросов. Подождите несколько минут…», тесты в `apiError.test.ts` и `App.test.tsx`; сам лимит снят выключением Confirm email |
| 5 | Сайт на Netlify показал белый экран | Консоль браузера: `Invalid supabaseUrl: Must be a valid HTTP or HTTPS URL` | Значение `VITE_SUPABASE_URL` было введено неверно; после исправления и повторного деплоя без кэша открылась форма входа |

Из прежней версии проекта (DeadlineHub) сохранились подходы, но не код: например, группировка по неделям и вычисление статуса «просрочено» в этой теме не нужны и удалены.

**Анализ скриншотов мультимодальной моделью:** в этой версии не выполнялся: скриншоты каталога с новой темой ещё не сняты. Раньше для DeadlineHub агент просматривал скриншоты и нашёл проблему на телефоне (форма занимала первый экран); решение (форма сворачивается за кнопкой на узких экранах) сохранено и в `ToursPage`.

**Ошибки из консоли:** логгер выводит ошибки API одной JSON-строкой (`{"level":"error","context":"bookings.create",...}`), её удобно давать агенту целиком; так же разбирали белый экран на Netlify.

## 6. Адаптивная вёрстка (Шаг 6)

| Ширина | Раскладка |
|---|---|
| < 640 px (телефон) | Одна колонка, форма сворачивается за кнопкой «+ Добавить путёвку», кнопки действий на всю ширину, высота тап-целей 44 px |
| 640–1023 px (планшет) | Одна колонка, кнопки в ряд, фильтр и переключатель разделов в одной строке |
| ≥ 1024 px (десктоп) | Две колонки: форма слева (закреплена при прокрутке), каталог справа |

Медиазапросы заданы через префиксы Tailwind (`sm:`, `lg:`). Раскладка унаследована от прежней версии; для экранов с турами проверка эмуляцией на 375, 768 и 1280 px и на реальном устройстве **не проводилась**, это нужно сделать самому.

## 7. Оптимизация и рефакторинг (Шаг 7)

- Бизнес-логика вынесена в чистые функции и покрыта тестами; вход селекторов не мутируется.
- Места в карточках обновляются локально после брони и отмены, без лишней перезагрузки каталога.
- Подсчёт мест и проверка перебронирования вынесены в БД (триггер и check-ограничение), а не в клиент: так нельзя обойти защиту через API.
- Сборка с подключённым Supabase: JS 459 КБ (gzip 132 КБ). Для сравнения без Supabase замер в этой версии не делался.
- Ошибки сервера приведены к единому типу `ApiError` с понятными сообщениями на русском, добавлен тип `sold-out`.

**Наиболее эффективные приёмы работы с AI:**

1. Сначала правила и стек в `CLAUDE.md`, затем короткие задачи по шаблону RTCF.
2. «Чистая логика отдельно» + просьба сразу писать тесты: ошибки ловятся до интерфейса.
3. Уточняющие вопросы перед крупной сменой темы (где менять, какой функционал, что делать с базой) сэкономили переделки.
4. Работа агента в браузере (логи Supabase, настройки Netlify, консоль сайта) ускорила поиск причин, при этом ввод паролей и ключей оставался за студентом.
