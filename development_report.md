## 1. Техническое задание (Шаг 1)

ТЗ создано для этого задания (отдельное ТЗ из ДЗ 3 не использовалось).

| Пункт | Решение |
|---|---|
| Идея | Общий список дедлайнов студенческой группы |
| Стек | React 19 + TypeScript strict + Vite |
| UI-библиотека | Tailwind CSS 4 |
| Тесты | Vitest + Testing Library + jsdom |
| Данные | Слой `api/` с двумя реализациями: mock (ДЗ 4) и Supabase (ДЗ 5) |

**Основные функции (7, минимум 3):**

1. Список дедлайнов со статусом и подписью «через N дн.» / «просрочено на N дн.»
2. Добавление дедлайна (форма с валидацией полей)
3. Отметка «выполнено» / «вернуть в работу»
4. Удаление
5. Сортировка по срочности (просроченные и ближайшие сверху, выполненные внизу)
6. Группировка по неделям
7. Фильтр по предмету

**Нефункциональные:** адаптивность (от 375 px), тап-цели не меньше 44 px, состояния loading/error/empty, доступность (подписи полей, `aria-*`, `role="alert"`).

## 4. Компоненты и состояния (Шаг 4)

Использованы шаблоны из ДЗ 2: «генерация компонента по описанию» и «написание тестов». Пример промпта (по шаблону RTCF):

```
## Role
Ты — Senior React/TypeScript-разработчик.
## Task
Реализуй компонент DeadlineForm: поля «Название», «Предмет», «Срок сдачи», валидация при отправке,
ошибки под полями (aria-invalid, aria-describedby). После успешного создания форма очищается,
при ошибке сервера введённые данные сохраняются.
## Context
Проект DeadlineHub. Валидация вынесена в чистую функцию validateNewDeadline в validation.logic.ts.
Данные приходят через проп onSubmit: (input) => Promise<boolean>.
## Format
План, код с // path:, тесты Vitest + Testing Library, команда проверки.
```

**Состояния (loading / error / success):**

| Состояние | Что видит пользователь |
|---|---|
| loading | «Загружаем дедлайны…» (`role="status"`), кнопки действий блокируются на время запроса |
| error загрузки | Красный баннер с понятным текстом и кнопкой «Повторить» |
| error действия | Баннер над списком (запись остаётся на месте) |
| empty | «Пока нет дедлайнов. Добавьте первый через форму.» |
| success | Список карточек |

Данные для проверки отображения: `MOCK_SEED` (6 дедлайнов, разные статусы) в `mockDeadlinesApi.ts`. Ошибку можно вызвать адресом `/?mock=network-error`.

## 5. Тестирование и отладка (Шаг 5)

**Автоматические тесты: 63 теста в 10 файлах, все проходят** (`npm test`).

| Что проверяется | Файл | Сценарии |
|---|---|---|
| Форма | `DeadlineForm.test.tsx` | успешная отправка и очистка · ошибки валидации · сохранение данных при отказе сервера |
| Страница | `DeadlinesPage.test.tsx` | загрузка → список в нужном порядке · пустой список · ошибка загрузки · добавление · отметка выполненным · ошибка доступа при удалении · фильтр и группировка по неделям |
| Вход | `App.test.tsx` | форма входа без сессии · неверный пароль · короткий пароль · активная сессия · режим без auth |
| Логика | `*.logic.test.ts` | статусы, срочность, недели, валидация, фильтры (обычные, граничные, ошибочные случаи) |
| Ошибки API | `apiError.test.ts`, `supabaseDeadlinesApi.test.ts` | соответствие HTTP-статусов и типов ошибок, маппинг строк БД |

**Что нашлось при отладке (реальные случаи):**

| # | Проблема | Как нашли | Решение |
|---|---|---|---|
| 1 | Тест упал: «найдено несколько элементов с подписью "Предмет"». Это поле формы и фильтр списка | Вывод Vitest | В тесте искать по роли (`textbox` / `combobox`), а не по тексту. Для пользователей скринридера это два разных элемента управления, подписи оставлены. |
| 2 | Тест упал на порядке выполненных дедлайнов | Вывод Vitest, сравнение массивов | Ошибка была в ожидании теста, а не в коде: выполненные идут по убыванию срока. Тест исправлен, правило добавлено в комментарий. |
| 3 | На телефоне форма занимала весь первый экран, список уезжал вниз | Скриншот мобильной версии (`mobile_before_fix.png`), просмотр изображения агентом | Форма сворачивается за кнопкой «+ Добавить дедлайн» на экранах уже `lg`, после создания закрывается (`mobile_fixed.png`). |
| 4 | Линтер: `Date` вызывается в рендере, `useMemo` зависит от значения, которое меняется каждый раз | `npm run lint` | Время вынесено в хук `useNow` (обновляется раз в минуту), мемоизация стала рабочей. |
| 5 | Линтер: setState в эффекте при загрузке | `npm run lint` | Загрузка разделена на `fetchItems` (без смены статуса) и `reload` (для кнопки «Повторить»). Одно предупреждение осталось: линтер не различает, что setState вызывается после `await`. Это ложное срабатывание, оставлено намеренно. |

**Анализ скриншотов мультимодальной моделью:** агент открыл скриншоты (`docs/screenshots/`), проверил читаемость, отступы, перенос длинных названий и горизонтальный скролл. Для всех трёх ширин (375, 768, 1280 px) скрипт Playwright подтвердил отсутствие горизонтального скролла.

**Ошибки из консоли:** логгер выводит ошибки API в консоль одной JSON-строкой (`{"level":"error","context":"deadlines.list",...}`), удобно давать её агенту целиком.

## 6. Адаптивная вёрстка (Шаг 6)

| Ширина | Раскладка |
|---|---|
| < 640 px (телефон) | Одна колонка, форма сворачивается, кнопки действий на всю ширину, высота тап-целей 44 px |

Медиазапросы заданы через префиксы Tailwind (`sm:`, `lg:`). Проверено эмуляцией Chromium (Playwright) на 375, 768 и 1280 px. Реальное устройство не использовалось, это нужно проверить самому.

## 7. Оптимизация и рефакторинг (Шаг 7)

- Бизнес-логика вынесена в чистые функции и покрыта тестами.
- Срочность считается один раз на элемент (схема map → sort → map), вход не мутируется.
- Эффективная мемоизация выборки списка (`useMemo` + стабильное время из `useNow`).
- Сборка без Supabase: JS 240 КБ (gzip 75 КБ); с подключённым Supabase: 457 КБ (gzip 131 КБ). Мок-режим не тянет клиент в сборку.
- Ошибки сервера приведены к единому типу `ApiError` с понятными сообщениями на русском.

**Наиболее эффективные приёмы работы с AI:**

1. Сначала правила и стек в `CLAUDE.md`, затем короткие задачи по шаблону RTCF.
2. «Чистая логика отдельно» + просьба сразу писать тесты: ошибки ловятся до интерфейса.
3. Скриншоты вместо словесного описания: проблему с формой на телефоне нашёл просмотр картинки, а не тест.
4. Явные границы в промпте («UTC», «без новых библиотек») убирают лишние итерации.
